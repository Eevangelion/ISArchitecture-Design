# Description
Над проектом работают: Березикова Александра, Ботвиньева Екатерина, Платонов Иван. 

Архитектурная документация находится в файле [architecture.pdf](architecture.pdf).

Данный проект реализует интерпретатор командной строки, поддерживающий следующие операции:

- cat — вывести на экран содержимое файла;
- echo — вывести на экран свой аргумент (или аргументы);
- wc — вывести количество строк, слов и байт в файле;
- pwd — распечатать текущую директорию;
- grep - поиск регулярных выражений;
- exit — выйти из интерпретатора;

Если введено что-то, чего интерпретатор не знает — вызов внешней программы.
Также поддерживаются пайплайны (`|`) и работа с подстановками (`$`).

# Grep
Для реализации команды grep была выбрана библиотека [cxxopts](https://github.com/jarro2783/cxxopts). 
Причины выбора:
1. Header-only<br>
    Библиотека не требует отдельной сборки или установки, её достаточно подключить через один #include <cxxopts.hpp>.  
    Это особенно удобно для учебных и кроссплатформенных проектов — можно просто добавить FetchContent в CMakeLists.txt, и всё соберётся автоматически.
2. Современный интерфейс (C++17) <br>
    cxxopts написана в современном стиле, безопасна по типам и поддерживает работу с `std::string. 
3. Минимальная зависимость <br>
    В отличие от Boost.Program_options, библиотека не тянет за собой огромный фреймворк и не усложняет сборку.
4. Поддержка коротких и длинных ключей <br>
    Позволяет легко описывать опции вроде -i, -w, -A, а также позиционные аргументы (например, шаблон поиска и имя файла), что идеально подходит под поведение настоящего grep.
5. Хорошая документация и активная поддержка <br>
    Библиотека используется в реальных CLI-утилитах и активно обновляется.

Рассмотренные альтернативы
1. Boost.Program_options<br>
    Слишком тяжёлая, требует установки Boost и настройки путей.
2. CLI11<br>
    Мощная, избыточна для одной команды grep.
3. getopt<br>
    Устаревшие C-интерфейсы, не поддерживают типобезопасность и позиционные аргументы.

# Getting started

Чтобы воспользоваться приложением, необходимо склонить репозиторий в локальную директорию и перейти на ветку, связанную с интерпретатором.

```bash
git clone https://github.com/Eevangelion/ISArchitecture-Design.git 
cd ISArchitecture-Design
git switch hw1-simple-interpreter
```

После чего собрать (см. Build раздел) и запустить (см. Launch раздел) приложение. 

# Build

Для сборки проекта необходимо установить cmake и запустить следующую команду в корневой директории проекта:

```bash
cmake --build .
./interpreter
```

# Testing

Для запуска тестов необходимо собрать приложение и запустить следующую команду в корневой директории проекта:

```bash
ctest -V .
```
